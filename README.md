# Smart Expense Tracker API

A small REST API for tracking personal expenses, built with Node.js, Express,
and Jest.

Expenses are stored in a local JSON file (`data/expenses.json`), so there is no
database to set up. The folder and file are created automatically the first time
an expense is saved.

## Requirements

- Node.js 18 or newer
- npm

## Getting started

**1. Install dependencies:**

```bash
npm install
```

**2. Run the tests:**

```bash
npm test
```

Expected: `Tests: 22 passed, 22 total`.

**3. Start the server:**

```bash
npm start
```

Expected: `Expense Tracker API is running on http://localhost:3000`. The server
runs until you press `Ctrl+C`.

**4. Run the smoke test** (optional, Windows PowerShell). Leave the server from
step 3 running and open a second terminal:

```powershell
.\scripts\smoke-test.ps1
```

Expected: `All checks passed - every requirement works.`

It adds a few expenses, checks each requirement against the running server,
deletes what it added, and prints a pass/fail line per check. It is safe to run
against real data — it records the counts and totals before it starts, checks
how much they moved, and confirms your existing expenses are untouched at the
end. Add `-BaseUrl http://localhost:4000` if the server is on another port.

To use a different port, set `PORT` (for example `PORT=4000 npm start`). For
live reload while editing, use `npm run dev`.

## API

Base URL: `http://localhost:3000`

| Method | Path | What it does |
| --- | --- | --- |
| GET | `/` | Lists the available endpoints |
| GET | `/health` | Returns `{ "status": "ok" }` |
| POST | `/expenses` | Adds a new expense |
| GET | `/expenses` | Lists all expenses |
| GET | `/expenses?category=Food` | Lists only the expenses in that category (case-insensitive) |
| GET | `/expenses/summary` | Total of everything, plus a total per category |
| GET | `/expenses/summary/monthly` | Bonus: totals grouped by month |
| DELETE | `/expenses/:id` | Deletes one expense by its id and returns the deleted expense |

### Add an expense

```bash
curl -X POST http://localhost:3000/expenses \
  -H "Content-Type: application/json" \
  -d '{"title":"Lunch at canteen","amount":120.50,"category":"Food","date":"2026-01-15"}'
```

Response `201 Created`:

```json
{
  "id": "0f2b8d5a-1c9e-4a7b-9c31-5e6a7b8c9d01",
  "title": "Lunch at canteen",
  "amount": 120.5,
  "category": "Food",
  "date": "2026-01-15"
}
```

The `id` is generated by the server with `crypto.randomUUID()`.

### Field rules

| Field | Rule |
| --- | --- |
| `title` | required, non-empty string |
| `amount` | required, finite number greater than 0 |
| `category` | required, non-empty string |
| `date` | required, real calendar date in `YYYY-MM-DD` format |

If anything is wrong the API replies `400` with every problem listed at once:

```json
{
  "errors": [
    "title is required and must be a non-empty string",
    "amount must be greater than 0"
  ]
}
```

### List and filter

```bash
curl http://localhost:3000/expenses
curl "http://localhost:3000/expenses?category=Food"
```

The `?category=` filter is case-insensitive and returns an empty array with
`200` when nothing matches.

### Totals

```bash
curl http://localhost:3000/expenses/summary
```

```json
{
  "count": 3,
  "total": 175,
  "byCategory": { "Food": 150, "Travel": 25 }
}
```

### Monthly summary (bonus feature)

```bash
curl http://localhost:3000/expenses/summary/monthly
```

```json
{
  "months": {
    "2026-01": { "count": 2, "total": 140 },
    "2026-02": { "count": 1, "total": 60 }
  }
}
```

### Delete

```bash
curl -X DELETE http://localhost:3000/expenses/<id>
```

> On Windows PowerShell, `curl` is an alias for `Invoke-WebRequest`, so use
> `curl.exe` for the examples above.

```
│   ├── app.js             builds the Express app
│   ├── store.js           reads and writes the JSON data file
│   ├── validation.js      checks a new expense before it is saved
│   ├── routes/
│   │   └── expenses.js    all the /expenses routes
│   └── middleware/
│       └── errorHandler.js
└── tests/                 Jest + Supertest tests
```

## Notes on some decisions

- **`app.js` and `server.js` are separate.** `app.js` exports the Express app
  without starting it, so Supertest can call the routes in the tests without
  opening a real port.
- **Totals are rounded to 2 decimals.** Adding money as plain JavaScript numbers
  gives results like `0.30000000000000004`, so every total is rounded before it
  is sent back. There is a test for this.
- **The `/expenses/summary` routes are registered before `/expenses/:id`.**
  Express matches routes from top to bottom, so if `/:id` came first it would
  match `/expenses/summary` and treat `"summary"` as an id.
- **Tests use a separate data file.** They set the `DATA_FILE` environment
  variable to a temporary file, so running the tests never touches
  `data/expenses.json`.
- **`amount` must be finite.** `JSON.parse` turns an overflowing literal such as
  `1e400` into `Infinity`, and `JSON.stringify` writes that back out as `null`.
  Without the finite check the expense would be saved with no amount and the
  summary would quietly count it as 0, so it is rejected with `400`.
- **The data file is written through a temporary file.** `store.js` writes to
  `expenses.json.tmp` and renames it into place, because a rename is atomic. An
  interrupted write therefore cannot leave a half-written file that every later
  read would fail on.
- **The summaries tolerate a hand-edited data file.** `data/expenses.json` is
  meant to be readable and editable, so a row with an unreadable `amount` counts
  as 0 and a row with no usable `date` is grouped under `"unknown"`, rather than
  returning a `500`.
